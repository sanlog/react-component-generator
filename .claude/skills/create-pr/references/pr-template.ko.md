# PR 본문 템플릿

아래 구조를 그대로 사용한다. 괄호 안 안내문은 지우고 내용으로 대체한다. 해당 없는 섹션은 `해당 없음`으로 둔다.

```markdown
## 요약

(이 PR이 무엇을 바꾸는지 1~3문장. 변경 후 무엇이 달라지는지 중심으로 쓴다.)

## 변경 이유

(왜 필요한가. 해결하는 문제, 요구사항, 관련 이슈. 이슈가 있으면 `Closes #번호`.)

## 주요 변경 사항

- (리뷰어가 알아야 할 변경을 동작 단위로 3~6개. 파일 목록 나열 금지.)

## 테스트

- [ ] (실행한 검증 명령과 결과. 예: `bun run test` 22개 통과)
- [ ] (수동 확인한 시나리오. 실제로 확인한 것만 체크한다.)

## 리뷰 포인트

(리뷰어가 특히 봐 주었으면 하는 부분, 트레이드오프, 알려진 한계. 없으면 `해당 없음`.)
```

## 작성 기준

- 체크박스는 실제로 수행한 경우에만 `[x]`로 표시한다. 수행하지 않았으면 `[ ]`로 두고 이유를 덧붙인다.
- UI 변경이면 `요약`이나 `테스트`에 확인한 화면 동작을 한 줄로 적는다. 스크린샷은 사용자가 첨부한다.
- 파괴적 변경이나 마이그레이션이 있으면 `리뷰 포인트` 맨 위에 쓴다.
